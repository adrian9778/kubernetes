# 02. 阅读 Kubernetes 所需的 Go 基础

## 2.1 context 是生命周期树

顶层 signal handler 创建根 context，组件派生子 context。`ctx.Done()` 不是普通错误通道，而是停止契约。长循环通常写成：

```go
for {
    select {
    case <-ctx.Done():
        return
    case item := <-events:
        handle(item)
    }
}
```

不要在库函数内部随意使用 `context.Background()` 断开取消链；不要把 context 存入长期对象后又复用过期请求语义。Kubernetes 新代码逐步从 stop channel 迁移到 context-aware API，但两种形式仍并存。

## 2.2 goroutine 不等于无限并行

常见并发形态：一个 producer goroutine、固定数量 workers、同 key 串行、共享缓存读锁、专用 goroutine 管理 timer/heap。`wait.UntilWithContext` 用于周期循环，`wait.NonSlidingUntil` 的计时语义与执行耗时相关。

启动 goroutine 时要能回答谁负责停止和等待。只 `go fn()` 而没有 context、stop channel 或 wait group，往往意味着泄漏。

## 2.3 channel、condition variable 与队列

Workqueue 不只是 channel。它用 condition variable 唤醒等待 Get 的 worker，用 dirty/processing sets 去重。DelayingQueue 还有独立 waiting loop 和最小堆。阅读时不要只找 `chan`，要看锁保护的不变量。

## 2.4 锁和不可变对象

Kubernetes 常用 `sync.RWMutex` 保护 map/heap，但更偏好“写时复制或快照，读者只读”。Informer cache 对象必须视为不可变；Scheduler Snapshot 为单次周期提供稳定视图；配置通过 CompletedConfig 固化运行期不变量。

检查锁时关注：锁覆盖哪些字段、外部调用是否在持锁期间执行、回调会不会重入、返回值是否泄露内部可变指针。

## 2.5 interface 的阅读顺序

先找调用方需要的最小能力，再看真实实现和 fake。常见边界：

- `rest.Interface`：HTTP 请求。
- `cache.Store/Indexer`：本地对象缓存。
- `workqueue.TypedRateLimitingInterface`：业务重试。
- `framework.Plugin`：调度扩展。
- `kubecontainer.Runtime`/CRI client：运行时边界。
- `volume.VolumePlugin`、CSI 接口：存储边界。

接口不是越多越好。Kubernetes 中最有价值的接口通常隔离外部副作用、平台差异或插件扩展。

## 2.6 Options、Config、CompletedConfig

`Options` 接近用户输入，可缺省；`Config` 包含已经创建的 client、server、informer 等依赖；`CompletedConfig` 表示默认值和不变量已确认。典型顺序：

```text
NewOptions -> AddFlags -> Complete -> Validate -> Config -> Complete -> Run
```

这一模式使解析、验证、依赖创建和运行可分别测试，避免运行中重新解释 flags。

## 2.7 错误处理

配置错误应 fail fast；控制循环错误需要判断是否重试；NotFound 常表示对象已删除；Conflict 表示重新读取后重算；429/timeout 是暂时性错误；无效 spec 应写 condition 并等待用户修改，不能毫秒级无限重试。

`utilerrors.NewAggregate` 汇总多个独立验证错误。`errors.Is/As`、API error helpers 和 StatusReason 比字符串比较可靠。

## 2.8 日志、Event、Condition 和 Metric

- 日志解释内部决策，使用 key/UID 关联。
- Event 给用户短期诊断，可能聚合和过期。
- Condition 是对象当前结论，包含 type/status/reason/message/observedGeneration。
- Metric 反映速率、深度、延迟和错误趋势。

控制器不应仅打印日志而不更新可观察状态，也不应每轮写同一 status 制造事件风暴。

## 2.9 build tags 与平台文件

Linux、Windows 和 unsupported 实现经常分文件存在，例如 `_linux.go`、`_windows.go`、`_unsupported.go`。阅读网络、cgroup、mount、stats 时必须确认 build tag，不能把某平台实现当通用路径。

## 2.10 生成代码

`zz_generated.deepcopy.go`、generated client、informer、lister、protobuf 和 OpenAPI 文件是工具输出。规则是修改输入和 marker，再运行 `make update` 或对应生成脚本。阅读它们只需掌握模板结构和与手写接口的连接点。
