# 文档说明与约定
> **文档目标**：为 Kubernetes 建立新手可读、源码可定位、可指导重新实现的源码走读文档。
> **源码基准**：`k8s.io/kubernetes`，commit `82f9fd3d5d18f763a2b193d1dc54d72f6fd77c04`（2026-09-24），Go 1.27.0。

## 1. 覆盖范围
本文档库按四层组织，前三层覆盖全部核心组件；第四层（函数级解析）聚焦 **Pod 全生命周期链路**：
- kubectl 命令构造与 REST 请求发出
- kube-apiserver 请求处理链、REST 存储路由、etcd 写入
- kube-scheduler 调度框架与绑定
- kube-controller-manager 的副本控制（以 ReplicaSet 控制器为函数级样本）
- kubelet 同步循环、PodWorker、PLEG、状态上报
- CRI 运行时调用（sandbox/container）
- 横向基础机制：client-go informer 与 workqueue
- 其余控制器：Deployment、Job、CronJob、DaemonSet、GarbageCollector
- kube-proxy（Service/Endpoints 到 iptables/ipvs 规则）
- CRD（apiextensions-apiserver）与 API 聚合层（kube-aggregator）
- cloud-controller-manager 与 cloud-provider 接口
- kubeadm 集群引导
- CSI 存储（kubelet/plugin-manager/volume-manager 侧）
- 设备插件与 kubelet 网络边界（CNI 由容器运行时侧实现，本仓库给出边界定位）

本仓库之外的第三方实现（具体云 provider、具体 CSI/CNI/设备插件驱动、容器运行时内部）不属于源码可分析范围。

## 2. 主线场景
第二层与第三层围绕一个真实最小成功场景：

```bash
kubectl run nginx --image=nginx --restart=Never
```

该命令创建一个裸 Pod（不经过 Deployment/ReplicaSet），主路径为：kubectl → apiserver → etcd → scheduler → bind → kubelet → CRI → status 回写。控制器层级（Deployment→ReplicaSet→Pod）在第四层 08 篇单独分析。

## 3. 源码定位规则
权威定位链路：**文件路径 → 模块 → 类型 → impl → 函数 → 函数内相对偏移**。

- 函数内偏移以函数定义行为 `+0`，如：`pkg/kubelet/kubelet.go 函数：syncLoopIteration 偏移：+30 ～ +45`。
- 非函数代码用稳定符号定位，如：`Struct：Kubelet 字段：podWorkers`、`Const：DefaultLegacyAPIPrefix`。
- 调用关系同时标注调用方与被调用方，必要时标注调用点偏移。
- 相对偏移是辅助手段，会随代码变动失效；符号路径（文件+类型+函数名）是首要依据。
- 本仓库的 `staging/src/k8s.io/` 是 `k8s.io/*` 各模块的源码真身；vendor 目录只是其同步产物。文中 `[staging]` 标记表示文件位于 staging 下。

## 4. 当前分支与上游的差异（实际验证）
本 checkout 相对上游 Kubernetes 存在以下差异，文档一律以当前源码为准：
- etcd 客户端为魔改版：`etcd3.store.client` 类型是 `go.etcd.io/etcd/client/v3/kubernetes.Client`，写入调用 `OptimisticPut`；etcd3 包内不存在独立的 `Write` 函数。
- 调度队列位于 `pkg/scheduler/backend/queue`（上游为 `pkg/scheduler/internal/queue`）；不存在 `generic_scheduler.go`，节点过滤逻辑在 `pkg/scheduler/algorithm.go`。
- kubelet 中不存在 `dispatchWork` 符号，该职责由 `podWorkers.UpdatePod` 承担（`pkg/kubelet/pod_workers.go`）。
- kubectl apply 位于 staging `k8s.io/kubectl/pkg/cmd/apply`，旧路径 `pkg/kubectl/apply` 不存在。
- client-go workqueue 已泛型化：`Type = Typed[any]`。

## 5. 真实性原则
所有结论来自当前源码实际验证。无法由源码证明的内容，明确写"当前源码无法确定"，不做推测性补充。函数签名、调用关系、参数与返回值均以源码为准。

## 6. 术语
| 术语 | 含义 |
|---|---|
| 控制面（Control Plane） | apiserver、scheduler、controller-manager、etcd 的集合 |
| 节点面（Node） | kubelet、kube-proxy 与容器运行时 |
| RESTStorage | 实现 `rest.Storage` 能力接口（Creater/Getter/Lister…）的资源存储对象 |
| Strategy | 资源的默认化、名称生成、校验策略（如 podStrategy） |
| Admission | 准入控制，分 mutating（Admit）与 validating（Validate）两阶段 |
| CRI | Container Runtime Interface，kubelet 与容器运行时之间的 gRPC 协议 |
| PLEG | Pod Lifecycle Event Generator，周期性比对运行时现状生成生命周期事件 |
| Informer | client-go 的 List/Watch + 本地缓存事件机制 |
| Assume | scheduler 绑定前在调度缓存中"假定"Pod 已占用节点的乐观操作 |
